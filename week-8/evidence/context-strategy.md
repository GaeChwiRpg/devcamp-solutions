# Context Strategy — 사용한 컨텍스트 + Needle 관리 전략

> 교재 1·2번 요소: 3 유형 컨텍스트 + 긴 대화에서 컨텍스트 유지.

## 사용한 컨텍스트 유형

이번 미션은 **A. 텍스트·코드 컨텍스트** + **B. 파일·문서 컨텍스트** 두 유형 사용. 이미지 컨텍스트는 사용 안 함.

### A. 텍스트·코드 컨텍스트

- baseline `Product.java`, `ProductRepository.java`, `ProductService.java`를 prompt에 그대로 inline 첨부.
- "이 파일들의 인덱스 활용 가능 지점을 찾아라" 형식의 목표와 함께 전달.
- **나쁜 예시 회피**: 단순히 코드 복붙 + "이거 봐줘" → 의도 모호. 반드시 "왜 보는지(목표)"를 같이 줌.

### B. 파일·문서 컨텍스트

- `evidence/seed-data.sql` (10만 row 시드)를 `@evidence/seed-data.sql` 참조로 전달.
- `application.yml`을 통해 H2 모드 / format_sql 옵션을 같이 보여줌 → AI가 어떤 환경에서 측정하는지 이해.

## Needle in a Haystack 관리 — 사용 전략

총 4시간짜리 작업 세션 동안 대화가 200 turn 가까이 늘어남. 교재의 3 전략 중 **2번 (`claude.md` GPS)** 와 **3번 (`/clear` 리셋)** 둘 다 사용.

### 전략 2 — `claude.md` GPS

- 위 `claude-md-snapshot.md`에 박아둔 도메인 컨텍스트가 절대 변하지 않음.
- 대화가 길어져도 AI가 매번 schema를 다시 묻지 않음.
- **효과**: 같은 schema를 prompt에 다시 적는 횟수 평균 4회 → 0회.

### 전략 3 — `/clear` 리셋

- 인덱스 미션을 끝내고 evidence 작성 단계로 넘어갈 때 `/clear` 사용.
- 이유: 인덱스 후보 비교의 산탄총 같은 reasoning이 evidence 작성 흐름을 오염시킬 수 있다는 판단.
- **효과**: evidence 작성 첫 응답이 깨끗하게 표 형식으로 나옴. 만약 이전 세션이 그대로였다면 AI가 인덱스 후보 비교에 미련 가진 응답이 나왔을 것.

## 안 쓴 전략과 이유

- **전략 1 (요약)**: 이번 미션은 4시간 짜리라 요약까지 갈 필요 없었다. 8시간 이상 세션에서 다음 적용 예정.

## 측정 효과

| | 컨텍스트 박지 않음 | 박은 후 |
| --- | --- | --- |
| 같은 정보를 prompt에 다시 적는 횟수 | 평균 4회/세션 | 0회 |
| AI가 schema를 잘못 가정한 경우 | 1회 | 0회 |
| 4시간 세션 후반부 응답 일관성 | 흐려짐 | 일정 |

## 다음 미션에서 가져갈 것

- `/clear`는 미션 phase 전환 시점(분석 → 측정 → 정리)에 강제 사용 규칙으로.
