# Workflow Before / After — 사람-only vs AI-native

> 교재 6 요소를 모두 적용한 후의 워크플로우가 사람-only 대비 어떻게 다른지 정량 비교.

## 비교 대상 미션

Week 4 인덱스 미션을 두 번 풀었다. 같은 baseline에서 시작해서 같은 evidence 파일을 산출하는 조건.

## 워크플로우 단계별 비교

| 단계 | 사람-only | AI-native (6 요소 적용) |
| --- | --- | --- |
| 시드 데이터 만들기 | 직접 SQL 작성, 30분 | AI에게 schema + "10만 row 시드" prompt, 5분 |
| 인덱스 후보 brainstorm | 2개 떠올림 (단일 / 복합) | 3개 떠올림 (+ price 후보 — AI가 던진 옵션) |
| EXPLAIN ANALYZE 실행 | H2 CLI 직접, 후보당 8분 | `/run-explain` 커스텀 command 1분 |
| 응답시간 측정 (hey) | 수동 명령 + 결과 정리, 25분 | 같음 (AI가 hey 측정을 자동화하지는 않음) |
| evidence 표 작성 | 직접 작성, 35분 | 페목형제 prompt로 초안 5분 + 검수 5분 |
| report 작성 | 35분 | 30분 (양은 비슷, AI 도움은 review에 집중) |
| **합계** | **약 3시간 30분** | **약 1시간 30분** |

## 정량 지표

| 항목 | 사람-only | AI-native | 변화 |
| --- | --- | --- | --- |
| 총 소요 시간 | 약 210분 | 약 90분 | -57% |
| 고려한 인덱스 후보 수 | 2 | 3 | +1 |
| AI hallucination 발견 수 | n/a | 2 | (검증으로 잡음) |
| 페목형제 prompt 후처리 시간 | n/a | 평균 1.6분 | (제약 효과) |
| 작업 경계 위반 시도 | 0 (스스로 안 함) | 1 (hook이 차단) | (-) |

## 검증 루프 비교

- **사람-only**: 본인 reasoning만 검증. 다른 후보의 trade-off는 시간 부족으로 깊게 못 봄.
- **AI-native**: AI가 만든 후보·표·표현을 사람이 evidence 단계에서 한 번 더 보면서 검증. EXPLAIN 결과는 무조건 직접 측정해 검증 (claude.md 검증 규칙).

## 실패 패턴 비교

- **사람-only**: 측정 도구 선택을 안 비교하고 익숙한 도구만 사용 → 학습 폭 좁음.
- **AI-native**: AI가 도구 후보 메뉴를 제시(MEASUREMENT-OPTIONS.md와 정합) → 학습 폭 +1, 단 도구 선택 근거를 사람이 직접 적어야 통과.

## 결론

AI를 쓴 사실이 시간을 줄인 게 아니라, **6 요소(특히 claude.md + commands + hooks)가 반복을 줄였다**. AI가 자유롭게 답하게 두었다면 후처리 시간이 더 늘어났을 것 — `prompt-pack.md`의 페목형제 적용 전/후 비교 참고.
