# Failure Cases — AI가 잘못 답한 사례 + 검증 루프

> AI를 신뢰 가능한 협업자로 쓰려면 실패 사례를 의식적으로 잡아내야 한다.

## 사례 1: hallucination — 측정 안 한 응답시간을 만들어냄

### 무엇이 일어났는가

페목형제 적용 전, "이 인덱스를 적용하면 응답시간이 어떻게 좋아질까?"라고 물었더니 AI가 다음 표를 만들어냄:

```
| | p50 | p95 |
| --- | --- | --- |
| before | 145ms | 198ms |
| after | 12ms | 38ms |
```

매끄럽고 그럴듯한 숫자. 하지만 **AI는 이 측정을 한 적이 없다.** 일반 RDBMS 사례에서 가져온 추정치를 권위 있게 적었다.

### 어떻게 잡았는가

evidence 작성 단계에서 본인이 hey로 직접 측정했더니 (p50 142, p95 198 → p50 18, p95 41) AI 추정치와 작은 차이. **이번엔 우연히 비슷했지만, 다음 미션에서는 큰 차이가 날 수 있다는 신호.**

### 어떻게 수정했는가

claude.md의 "검증 규칙"에 다음 줄 추가:

> AI가 만든 응답시간 추정 수치는 evidence에 사용 금지. evidence는 본인이 hey로 직접 측정한 결과만.

이후 prompt 3개 모두에 같은 제약을 [제] 칸에 명시 → hallucination 0회.

### 학습

AI는 모르는 것에 대해 **"모른다" 대신 "그럴듯한 추측"을 만들어낸다**. 측정값처럼 검증 가능한 도메인은 반드시 본인 측정으로 한 번 더 검증.

## 사례 2: 작업 경계 위반 시도

### 무엇이 일어났는가

evidence 작성 중반에 AI에게 "메인 README에도 인덱스 미션 안내 한 줄 추가해줘"라고 요청. AI가 루트 README를 수정하려고 시도. PR diff에 미션 폴더 외 변경이 들어가면 mission-guard CI fail이 발생할 상황.

### 어떻게 잡았는가

PreToolUse hook (`check-mission-scope.sh`)이 작업 시점에 차단. 만약 hook이 없었다면 PR 단계에서 CI가 잡았을 텐데, push 후에 발견하는 게 시간 손실.

### 어떻게 수정했는가

AI가 "현재 미션 디렉토리 외부 수정이 차단되었습니다. 미션 폴더 안 README에 추가하거나, 사용자가 main의 README를 직접 업데이트하시겠어요?"로 대안 제시. 사용자가 해당 작업을 별도 작업(다음 PR)으로 분리.

### 학습

AI는 사용자의 의도를 좋게 해석하려 하지만, 그 과정에서 **작업 경계를 침범**한다. hook이 없으면 reviewer가 매번 PR diff를 직접 봐야 함. hook이 그 부담을 1차 차단.

## 사례 3: 인덱스 후보를 너무 적극적으로 추천

### 무엇이 일어났는가

"인덱스 후보 비교해 줘" 첫 prompt에서 AI가 5개 후보를 제시 + 각각에 인덱스 추가 DDL을 같이 작성. 그 중 (price, title) 같은 비합리 후보도 권위 있게 트레이드오프 분석을 적었다.

### 어떻게 잡았는가

본인이 검토 단계에서 "이 후보가 우리 정렬 키 created_at과 어떻게 연결되는가?"를 직접 트레이싱. (price, title)은 정렬 키 충족 X. AI는 그 부분을 흐리게 적고 "trade-off 있음"으로 처리했다.

### 어떻게 수정했는가

페목형제 적용 후 prompt 1을 다음과 같이 재작성:

```
[제] 후보는 정렬 키(`created_at DESC`)를 활용 가능한 것으로만 좁힐 것.
     충족 안 되는 후보는 처음부터 제외.
```

이후 응답에서 후보가 3개로 깔끔하게 줄어들고 모두 정렬 키 충족.

### 학습

AI는 "더 많은 옵션을 보여주는 게 도움이 된다"고 판단하면 비합리 후보까지 포함시킨다. 제약을 미리 박지 않으면 비교 폭은 커지지만 노이즈가 늘어남.

## 정리: 검증 루프

| 단계 | 검증 방법 | 잡힌 사례 |
| --- | --- | --- |
| prompt 작성 시 | 페·목·형·**제** 4요소 강제 | 사례 3 (제약으로 미리 차단) |
| AI 응답 받은 직후 | claude.md 검증 규칙 적용 | 사례 1 (수치 추정 차단) |
| 도구 호출 시 | PreToolUse hook | 사례 2 (경로 위반 차단) |
| evidence 작성 시 | 본인이 직접 실측으로 한 번 더 | 사례 1 재차 검증 |

**핵심**: AI 결과를 그대로 evidence에 옮기면 안 된다. **검증 루프 4 단계 중 최소 2개**를 통과한 결과만 evidence에 들어간다는 원칙.
